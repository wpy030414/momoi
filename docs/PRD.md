# PRD — Momoi 产品需求文档

## 产品定位

Momoi 是一个**轻量级、可自托管的 Web AI 智能体平台**。它的核心价值是让个人或团队能够快速部署一个属于自己的 AI 助手，通过插件扩展能力、通过技能注入知识、通过文件附件实现多模态交互，并通过管理员面板灵活配置一切。

## 目标用户

- **个人开发者**：想要一个自托管的 AI 聊天界面，对接各种 OpenAI 兼容的模型 API
- **小团队**：需要一个内部的 AI 助手，能通过插件接入内部工具和数据
- **AI 应用开发者**：需要一个可快速迭代的 AI Agent 原型平台

## 核心用户场景

### 场景 1：登录与日常对话

用户打开网页 → 输入用户名 → 输入 4-8 位 PIN 登录 → 开始与 AI 对话 → 看到流式输出的回复 → 点击建议继续追问。

### 场景 2：使用内置工具

用户提问涉及外部数据 → AI 自动调用内置工具（如搜索、查询数据库）→ 工具结果返回 → AI 基于结果生成最终回复。

### 场景 3：发送文件附件

用户在输入框附加文件（图片、Excel、PDF 等）→ 文件上传并解析 → AI 基于文件内容进行多模态回答（如识图、分析表格、解读 PDF）。

### 场景 4：管理员配置

管理员（`ADMIN` 名单内用户）点击侧边栏设置图标 → 直接进入「后台设置」（无需密钥）→ 修改模型配置/系统提示词 → 上传新插件/技能 → 配置立即生效，无需重启。普通用户没有该入口，直接访问 `#/settings` 会被路由守卫遣返首页。

### 场景 5：对话管理

用户在侧边栏查看所有对话历史 → 切换对话 → 重命名或导出对话 → 从某条消息回退重新对话 → 删除对话。

### 场景 7：创造并观察一个世界

用户点击侧边栏「新工作流」→ 选择「世界模拟」→ 挑选至少一个 Agent → 写下一段世界描述（地形规则与世界法则）→ 确认。世界在一秒内创生，用户进入三维沙盘：先看到「大地正在成形……」，随后地形浮现。用户可以拖拽旋转视角、滚轮或双指缩放；查阅世界信息卡上的地形摘要；打开法则编辑器修改世界法则（地形规则只读）。刷新页面或换一台设备打开，看到的是同一片大地。

### 场景 6：管理员数据浏览

管理员进入统计面板 → 查看用户数/对话数/消息数 → 浏览所有对话列表 → 展开查看具体对话的消息内容。

## 功能需求

### F1：用户认证

- 用户名 + 4-8 位数字 PIN 登录
- 首次使用自动引导设置 PIN
- PIN 使用 PBKDF2 安全哈希存储
- JWT Token 14 天有效，剩余不足一半自动续期（应用打开期间免重复登录；超 14 天未使用需重新登录）
- 支持修改 PIN（需验证旧 PIN）
- 登出功能

### F2：聊天界面

- 流式输出（token 逐字显示）
- 思考过程展示（可折叠，支持 AI 扩展推理模式）
- 工具调用展示（调用名 + 输入参数 + 结果摘要）
- 文件附件展示（图片预览、文件卡片、下载）
- Mermaid 图表渲染
- 后续建议（3 条可点击的追问）
- 中断/取消正在进行的对话
- 消息回退（从任意消息处删除并重新对话）

### F3：对话管理

- 创建新对话
- 查看对话列表（按更新时间排序）
- 切换对话（加载历史消息）
- 重命名对话
- 删除对话（级联删除消息）
- 导出对话为 TXT 文件
- URL 哈希路由（`#/c/{id}`）支持浏览器前进后退

### F4：工具系统

- 12 个内置工具：文件读写、网络请求、文档处理、技能加载、bash 命令、群聊 @mention、用户提问、跨会话记忆
- 工具作为 Agent 的基础能力，在沙盒化对话工作区中执行
- 所有工具均通过 function calling 由 AI 自动调用
- Pi Agent Core 提供并行执行、TypeBox 参数校验

### F5：技能系统

- 技能通过递归扫描 `skills/` 目录树自动发现（任何含 `SKILL.md` 的目录都注册为技能）
- 名称和描述注入系统提示词，完整内容通过 `load_skill` 工具按需加载
- 支持 `list_skill_files` 工具发现技能内部文件结构
- 支持嵌套子技能（如 `yida-skills` 下的子技能目录）

### F6：文件附件

- 支持上传图片（→ base64 多模态）、Excel（→ CSV）、PDF（→ 文本）、纯文本文件
- 输入框附件上传按钮，可切换开关
- 管理员可全局开关附件功能（`support_attachments` 配置）
- 上传限制 20MB，文件以 UUID 重命名存储
- 附件信息持久化到消息记录

### F7：管理员面板

- `ADMIN` 名单内用户免密钥直入（复用用户 JWT，逐请求校验名单）
- Agent 管理（创建/编辑/删除 Agent，配置模型和提示词）
- Gateway 配置（全局 API 地址、密钥）
- 品牌配置（应用名称、Favicon、聊天背景图）
- MCP 服务器管理（添加/编辑/删除/启用禁用 MCP 服务器）
- 技能管理（列表/上传/卸载）
- 统计面板（用户数/对话数/消息数 + 对话浏览）

### F8：国际化

- 中文（默认语言）
- 英文
- 语言偏好持久化到 localStorage

### F9：主题

- 浅色/深色模式
- 跟随系统偏好
- 偏好持久化到 localStorage

### F10：Agent 多智能体系统

- 每个 Agent 独立配置模型、系统提示词、头像
- 默认 Agent（Momoi）自动创建，中立 Agent 内置不可删除
- 管理员可创建/编辑/删除 Agent（中立 Agent 不可删除、不可改名）
- 首次启动自动从旧全局配置迁移创建默认 Agent 和中立 Agent

### F11：群聊对话

- 创建群聊对话，选择多个 Agent 参与
- Agent 依次串行回复，前序发言以 user 角色 + 名字前缀注入后续 Agent 上下文
- 每轮开始前由中立 Agent 裁决参与成员：已退场 / 不懂当前话题者可暂不发言，用户点名者强制参与
- @mention 工具：Agent 可点名调用其他 Agent，被点名者优先应答（其余 Agent 照常发言）
- 系统提示词注入 Agent 身份（姓名、群组成员列表）
- 群聊对话侧边栏显示参与人数

### F12：无限演算模式

- 个体聊天或群聊中均可开启，中立 Agent 自动生成追问
- 追问以用户口吻生成（问题、反问、动作描述）
- 可随时关闭，关闭后发送 `infinite_mode_off` 事件
- 追问以 `follow_up` SSE 事件下发

### F13：IP 速率限制

- PIN 验证连续 5 次错误 → 封禁 IP 5 分钟
- 内存级状态，重启服务即清除
- 定时清理过期条目，防止内存泄漏
- 验证成功后自动清除失败记录

### F14：MCP 客户端支持

- 通过 HTTP+SSE 连接外部 MCP 服务器（JSON-RPC 2.0）
- 管理员可配置多个 MCP 服务器（名称/URL/启用状态）
- MCP 工具自动注入 Agent 工具列表，与内置工具统一调用（`{serverName}/{toolName}` 命名空间）
- 工具列表缓存（5 分钟 TTL），MCP 服务器故障时优雅降级
- 不依赖 `@modelcontextprotocol/sdk`，手动实现 HTTP 传输

### F15：OAuth2 登录

- 管理员可在后台配置多个 OAuth2 提供商（名称、ID、授权 URL、Token URL、UserInfo URL、Client ID/Secret、Scopes）
- OAuth 提供商信息通过 `/api/oauth/providers` 公开暴露（仅 ID 和名称，不暴露密钥）
- OAuth 登录流程：浏览器跳转提供商授权页 → 回调验证 state（防 CSRF）→ 换取 access_token → 查询 UserInfo
- 回调路由通过 Referer 头自动推断 SPA 前端 origin（兼容开发代理模式）
- 已有绑定的 OAuth 身份直接登录，签发 JWT Cookie
- 已登录用户使用 OAuth 时自动绑定当前账号（无需二次验证）
- 全新 OAuth 用户进入注册页面，支持两种模式：
  - **绑定已有账号**（action=link）：提供已有用户名+PIN，验证通过后绑定 OAuth 身份
  - **创建新账号**（action=create）：提供用户名+PIN，创建账号并绑定
- OAuth 注册受 `oauth_registration_open` 开关控制，管理员可随时关闭
- OAuth 绑定以 `(provider_id, provider_user_id)` 唯一约束防止重复绑定
- 账号被封禁（banned）时禁止 OAuth 登录

### F16：IM 绑定（微信 / QQ）

统一入口「在 IM 上继续」：侧栏 direct 会话右键 → 弹出渠道选择（微信 / QQ 两卡片）→ 进入对应绑定流程。两渠道**完全正交**——同一会话可同时绑定微信与 QQ，各自独立路由、互不干扰。

#### 微信渠道

- 用户通过网页端扫码绑定微信个人机器人（基于腾讯 iLink 协议），非群机器人
- **绑定流程**：网页端发起绑定 → 后端调用 iLink 获取 QR Code → 服务端渲染二维码为 data URI 返回前端 → 用户用微信扫码 → 前端轮询扫码状态 → 确认后保存 bot_token 到数据库
- **会话锚定**：绑定时可指定目标一对一对话 ID，后续微信消息路由到该对话；未指定则沿用已有绑定的会话
- **覆盖转移（换绑）**：重新扫码绑定到新会话即完成转移，旧会话不再接收微信消息——路由权威即 `wechat_bindings.conversation_id` 字段本身
- 会话删除时自动清除绑定（poller 自愈 + 删除时级联清理），防止僵尸绑定
- 绑定操作受每用户串行锁保护，防止并发扫码覆盖
- **微信消息接收**：poller 每 5 秒轮询所有已绑定用户的 iLink 消息更新
- **消息去重**：基于 iLink message_id 的内存去重缓存（5 分钟窗口），防止长轮询重复投递
- **消息路由**：发送者校验 + 会话存活检查 + 合法性过滤（仅绑定用户的 wechat_user_id 可发消息）
- **AI 桥接**：微信文本直接送入 `runPiAgentLoop`，历史消息加载、思考过程、后续建议均写入消息记录；不依赖 HTTP/SSE 层
- **消息回复**：AI 回复通过 iLink sendMessage 发送，带 3 次指数退避重试（1s/2s/4s）；session 过期自动标记 `session_expired`
- **失败提示**：微信推送失败时（如 token 过期），在对话中插入系统消息 `[WeChat推送失败]` 提醒用户
- 内置命令 `/clear`、`/new`、`/reset` 直接在微信端响应"会话已重置"
- 未绑定会话时微信消息回复"尚未绑定会话"提示
- 解绑 API 支持主动断开微信绑定

#### QQ 渠道

- 用户在 [QQ 开放平台](https://q.qq.com)创建个人机器人，仅需提供 **AppID + AppSecret** 即可绑定（凭证式绑定，无扫码）
- **凭证校验**：绑定时服务端即时校验凭证（获取 access_token），失败在表单内联反馈原因，不落库不起连接
- **连接方式**：WebSocket 网关出站长连接（无需公网 IP），服务启动自动恢复所有已绑定用户的连接；仅处理 C2C 私聊，群聊静默忽略
- **无认领模型**：个人机器人私聊者必然是用户本人（1 用户 : 1 机器人 : 1 会话），不校验发送者身份
- **会话锚定 / 换绑**：与微信同语义，路由权威为 `qq_bindings.conversation_id`；换绑会话无需重新输入凭证
- **凭证保留式解绑**：软删会话仅清除路由目标、保留凭证与连接（AppSecret 遗失需在开放平台重新生成，成本高）；显式解绑才删行断连
- **流式回复**：AI 回复通过 `stream_messages` API 以打字机效果流式呈现（全量 replace 帧 + 800ms 节流 + 频控退避）；流式链路故障自动降级为分片一次性发送
- **跨渠道串行化**：微信与 QQ 消息共享同一 per-user 锁，双渠道绑同一会话时 AI 调用串行执行，防止历史交叉
- 内置命令与微信一致；未绑定会话 / 推送失败提示行为与微信一致（`[QQ推送失败]`）

### F17：TTS 语音合成

- 支持两种 TTS 引擎后端：**GPT-SoVITS**（默认）和 **CosyVoice**
- TTS 引擎通过 HTTP API 对接（GPT-SoVITS 端口 9880、CosyVoice 独立端点），服务端负责调用并缓存音频
- 管理员可在后台配置 TTS 引擎的 API 端点地址和引擎类型
- **每个 Agent 可独立配置声音**：
  - 上传声音样本音频（参考录音）
  - 生成或注册 voice_id/speaker_id
  - 启用/关闭语音合成
  - 配置语音参数（语速、音调等）
- 语音合成在每次 AI 回复后异步执行，按句子分段生成 WAV 音频文件，存于 `data/voice/{agentId}/{messageId}/`
- 每段语音记录元数据到 manifest.json（文本、段数、完成状态）
- 前端通过 `/api/voice/segments` 端点查询语音片段列表，按需加载音频播放
- 音频以 32kHz mono 16bit WAV 格式缓存，时长通过文件大小估算

### F18：多设备实时同步

- 同账号多设备间通过 **SSE 事件总线**（进程内内存态）实现实时数据同步，无需手动刷新
- 每个已登录设备保持一条到 `/api/events` 的 SSE 长连接
- **聊天流中继**：用户在一台设备上对话时，聊天流事件（token 流式输出、工具调用、思考过程）实时推送给同账号下的其他设备
- **来源设备自跳过**：聊天流事件携带 `deviceId`，源设备不重复推送（源设备已通过 POST `/api/chat` 的 fetch 流直接渲染）
- **会话列表同步**：会话创建/删除/重命名时广播 `conv_sync` 事件，各设备侧边栏自动更新
- **会话内容变更**：消息回退等操作广播 `conv_changed` 事件，正查看该会话的设备自动重新拉取消息
- **群成员变更**：群聊成员变动广播 `group_members` 事件
- 设备重连时自动去重同一 `deviceId` 的旧订阅（防御 React StrictMode 双挂载）
- 广播时惰性清理已断开的订阅，防止异常断线时内存泄漏

### F19：ask_user 工具

- 向 AI Agent 提供阻塞式用户询问能力——Agent 在需要用户决策时调用此工具暂停执行
- **核心机制**：`execute()` 返回一个不 resolve 的 Promise，Pi 循环自然等待；通过 `ctx.onUpdate` 触发 `tool_execution_update` SSE 事件，下发 `ask_user` 问题到前端
- 支持**多问题**：单次调用可提多个问题，每个问题包含标题、完整问题文本、预设选项
- **预设选项**：每个问题可带 2-4 个选项（label + description），单选/多选可选；选项为空时用户自由输入
- **超时处理**：120 秒未回答自动拒绝，返回超时错误给 Agent；SSE 断开时同步清理该会话所有挂起问题
- **回答端点**：`POST /api/chat/:id/answer` 接受 `questionId + answer + selectedOptions`，校验后 resolve 挂起的 Promise
- 支持 AbortSignal：用户取消对话时自动 reject 挂起问题

### F20：PostgreSQL 远程数据库模式

- 通过 `DATABASE_URL`、`DATABASE_USER`、`DATABASE_SECRET` 三个环境变量同时填写启用远程数据库
- 系统从 `DATABASE_URL` 的 scheme 自动识别数据库类型（`postgres://` 或 `postgresql://` → PostgreSQL）
- 未配置或三个变量缺一时使用默认的本地 **sql.js（SQLite 内存持久化）** 模式
- PostgreSQL 模式使用 `pg`（node-postgres）驱动 + `drizzle-orm/node-postgres` + `schema.pg.ts` 专用 Schema 定义
- 启动时自动执行 DDL：`CREATE TABLE IF NOT EXISTS` + `ALTER TABLE ADD COLUMN IF NOT EXISTS` 增量迁移
- 连接池配置：最大 5 个连接
- 两种模式导出统一的 `db` 对象和表定义，业务层无需感知底层数据库差异

### F21：直连注册开关

- 管理员可通过数据库设置项 `direct_registration_open` 控制直接 PIN 注册的开放状态
- 关闭后，新用户无法通过用户名+PIN 方式注册——仅已有用户可登录
- 关闭不影响管理员创建账号、OAuth 注册等替代注册路径
- 运行时热更新生效，无需重启服务

### F22：世界模拟（World Simulation）

创建流程使用统一的「新工作流」对话框：先选**模式**（群组会话 / 世界模拟），再选 Agent。

- **群组会话**：至少 2 个 Agent（既有行为不变，仍走草稿态）
- **世界模拟**：至少 1 个 Agent + 必填的世界提示词

世界模拟提供由提示词创生的**三维有限面积沙盘**，取代该会话消息气泡的位置：

- **提示词同时规定两件事**：**世界地形规则**（山地、丘陵、森林……未提及则随机生成自然地形）与**世界法则**（永久黑夜、伤害一律致命、水体有毒……）
- **地形规则创生后不可修改**（服务端拒绝，非仅界面隐藏）；**世界法则可随时更改**
- **地形生成**：LLM 只输出结构化参数（种子、噪声参数、水位分位、生物群系规则、天空预设），渲染所需的地形由客户端按同一份参数确定性生成 —— 故任何设备、任何时刻打开同一世界，看到的地形完全一致
- **相机**：鼠标拖拽 / 单指滑动旋转，滚轮 / 双指捏合缩放；**不平移**；相机不会钻到地面以下
- **有限沙盘**：世界有明确边界，不表现为无限延伸的地面
- **参与 Agent** 在创生时被安置到陆地上（落点确定性，刷新不变）
- **降级**：设备不支持 WebGL2 时自动切换为二维俯视地图（同一份地形数据的另一视角）

**回合制（已完成）**：世界是**回合制**的 —— 用户以「上帝」身份写下一步做什么并提交，所有存活 Agent 依次行动一拍，行动以**事件**实时流入世界视图的事件日志。Agent 可移动（沙盘名牌随之移动）、说话、观察、行动，并可依法则对彼此施加后果（包括不可逆的死亡）。世界的「历史」就是这张事件日志。

**已完成**：Phase 1（创生、地形生成与渲染、相机操作、法则编辑）；Phase 2（Agent 入场、回合制行动、事件日志、世界工具）。
**后续阶段（Phase 3）**：上帝 Avatar 的放置与邻近互动、Agent 改造世界、自动演算开关。

## 非功能需求

### NF1：部署简单

- 单进程部署，无需外部数据库（默认）
- `pnpm build && pnpm start` 即可运行
- SQLite 单文件存储（默认）
- 可选远程 PostgreSQL 替代方案

### NF2：兼容性

- 支持所有 OpenAI 兼容的 API（包括本地模型、第三方代理）
- 支持 thinking/reasoning 内容流式输出（如 DeepSeek、Qwen、DashScope）
- 支持多模态内容（图片 base64）
- 支持 Pi 式并行批执行（同一轮内多工具并发执行 + 顺序回填 + 批量终止）
- 漂移检测（连续重复工具批次自动终止）
- 支持多轮工具调用
- 支持 SQLite（本地 sql.js）和 PostgreSQL 两种数据库后端，业务层无需感知差异
- 世界模拟的三维渲染需要 **WebGL2**（three.js 自 r163 起已移除 WebGL1 支持）；不支持时自动降级为二维俯视地图。钉钉 Android 内置内核是主要风险点

### NF3：可靠性

- 客户端自动重试（最多 3 次，指数退避）
- SSE 15 秒心跳保活
- 60 秒空闲超时
- 微信消息轮询 5 秒间隔 + 每用户并发守卫（防止同一用户轮询重叠）
- 微信消息去重缓存（5 分钟窗口），防止 iLink 长轮询重复投递
- 微信消息回复 3 次指数退避重试（1s/2s/4s），失败时推送 MARKER 系统消息
- 微信 bot_token 写守卫：并发扫码或 token 轮换时，旧 token 的写入不污染新绑定行
- 微信绑定轮询器自愈：指向已删除会话的绑定自动清理
- ask_user 超时自动解除（120 秒），SSE 断线清理挂起问题
- 数据库每 30 秒自动持久化（SQLite 模式）

### NF4：安全性

- 管理员授权基于用户 JWT + `ADMIN` 名单逐请求校验（停机改 `.env` 即可即时收权），名单与 `JWT_SECRET` 不暴露给前端
- JWT 经 HttpOnly Cookie 传输（`HttpOnly; SameSite=Lax`，HTTPS 下 `Secure`），不进入 localStorage/响应体，XSS 无法窃取
- PIN 使用 PBKDF2（SHA-512、10000 次迭代、随机盐）安全哈希
- JWT 认证保护管理员和用户端点
- Zip slip 攻击防护
- 对话按用户隔离
- 时序安全的 PIN 比较（`timingSafeEqual`）
- OAuth 防 CSRF：state 参数经 HttpOnly Cookie 传递，回调时比对
- OAuth 账号封禁检查：banned 用户禁止登录
- OAuth 绑定唯一约束：`(provider_id, provider_user_id)` 防止账号冒用
- 微信绑定 sender 校验：仅绑定的 wechat_user_id 可发送消息路由到 AI
- 微信会话验证：目标会话被软删除后绑定自动清除，防止僵尸路由
- 注册开关：管理员可通过开关控制 OAuth 注册和直接 PIN 注册，控制用户准入

### NF5：Agent 可扩展性

- 支持多 Agent、多模型、多角色
- 每个 Agent 独立提示词，互不干扰
- 每个 Agent 独立声音配置（TTS 语音合成 + 声音样本）
- 默认 Agent + 中立 Agent 开箱即用
- 通过管理员面板即可增删 Agent，无需修改代码
